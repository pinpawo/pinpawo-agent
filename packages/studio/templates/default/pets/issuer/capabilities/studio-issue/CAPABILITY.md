# Studio Issue

主要调查 GitHub Issue 的正文、评论、关联 PR 的状态与已有审查和验证结果，并与 Channel 中的公开交付和人类决定对照。围绕这些来源识别重复事项、实际进度、尚未完成的内容和待决定的问题，复用已有结论。

通常无需阅读代码、检出工作区或复跑测试。只有上述材料不足以回答影响状态或安排的具体事实问题时，才做必要的小范围核查；缺少实现或独立验收证据时，说明缺口及所需帮助。代码实现、修复、补测试、独立代码审查和 Wiki 维护不属于本能力的交付。

交付是有来源的 Issue 状态结论、明确的待办、适合承接的成员及交接背景，或需人类决定的问题。待核实事项按单条或小批量组织，不一次要求核验全部 Issue。

依据已有授权和可靠结论维护 Issue 状态，区分尚未完成、有交付但待核验、已合并和已部署；信息不足时保留未确认状态，不把推测、PR 草稿或其他人的建议当作完成事实。
