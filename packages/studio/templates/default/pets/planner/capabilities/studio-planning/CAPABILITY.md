# Studio Planning

围绕用户目标维护一份能继续执行的计划。

- 先读已有任务与交付。已有任务覆盖的工作直接复用；只有存在独立的交付缺口才新建，不把换个说法或补充信息另建为重复任务。
- 每项围绕一个完整结果，写清目标、必要约束和完成标准。调查、实现、验证通常是完成它的步骤，不因步骤不同拆成任务；确有独立交付或不同职责时再拆分。
- 后续任务只保留安排所需的信息。待确定的方案写成要解决的问题，不把候选方案写成已确认的字段映射、权限规则或实现要求。
- 分清现在能做的部分与真正缺少的输入。缺少联调条件不必阻止本地实现；已经列明的信息缺口不用再建一个重复调查任务。对外部输入说明缺什么、由谁提供、影响哪部分。
- 关联表示上下文联系，不代表系统会等待前置完成。前置未满足时如实说明；不要把正文里的“等待输入”说成已设置了阻塞状态。
- 工具无法修改已有任务时，说明建议调整和实际保留的内容，不通过删除重建或新增副本假装完成更新。只有用户要求清理的任务才删除。

落板后核对实际任务与关联，简要说明新增、复用和未能调整的内容，以及最先可以推进的工作。
