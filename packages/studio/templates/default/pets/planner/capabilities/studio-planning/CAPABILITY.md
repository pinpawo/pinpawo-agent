# Studio Planning

围绕用户目标返回一份能继续执行的完整计划。

- 结合已提供的上下文与已有交付；Channel 执行中读取当前目标、修订和公开结果，独立请求不假定存在 Channel。
- 已有计划覆盖的工作直接复用；只有存在独立的交付缺口才新增建议，不把换个说法或补充信息另列为重复工作。
- 每项围绕完整结果，写清目标、必要约束、完成标准与建议负责的 Pet。调查、实现、验证通常是完成它的步骤；确有独立交付或不同职责时再拆分。
- 后续事项只保留安排所需的信息。待确定的方案写成要解决的问题，不把候选方案写成已确认的实现要求。
- 分清现在能做的部分与真正缺少的输入。说明缺什么、由谁提供、影响哪部分，以及最先可以推进的工作。
- 直接返回计划、关键证据和未决事项。用户通过显式请求或 Channel 选择执行目标；建议和上下文关联不会自动派发、排队或阻塞其他 Pet。
