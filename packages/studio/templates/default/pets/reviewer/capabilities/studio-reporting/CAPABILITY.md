# Studio Reporting

根据交接的 Kanban `taskId`、最终结果和证据，反馈整个看板任务的结果。

- 先读取看板中的任务要求、状态及已有结果，对照本次交接，确认反馈对应的是同一个任务。
- 完成反馈使用 `kanban_task_complete`：提交最新的完整结果，包含交付位置、关键结论、验证证据，以及风险或仍需关注的问题。后续工作读取的是这份看板结果，因此不要只写“已完成”或让读者去找聊天记录。
- 结果区分已验证事实、建议和待确认事项。设计交付完成不表示用户已批准其中的产品或权限取舍；不要把本次范围外的待确认项一律变成当前任务的阻塞。
- 说明下一步最先能做什么、可复用哪个已有任务，以及真正缺少的输入。保留必要的结论与证据，较长正文附稳定的交付位置；不要用重复的历史记录淹没当前结果，也不要把建议说成已创建或已安排的任务。
- 审查任务的结果应明确通过或需要修正，并附具体证据；完成审查不等于被审查的实现已经通过。
- 确实无法继续时使用 `kanban_task_block`，说明已完成内容、阻塞原因和继续所需条件。
- 交接缺少结果或证据、仍有工作未完成时，说明需要补充什么，将问题交回 Pet 决定下一步。
- 根据工具返回核对反馈是否成功。已有完成结果与本次交接不一致时，说明差异和未能更新的内容，不把旧结果当成本次提交成功。

反馈结束后，说明实际写入看板的结果或尚未完成反馈的原因。
